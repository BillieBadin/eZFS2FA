## 2026-05-15 - v1.0.1

### Summary

This release delivers the `v1.0.0` -> `v1.0.1` transition by focusing on wrapper lifecycle reliability, safer in-memory key handling, and clearer operational guidance, with:

- wrapper format/version evolution support,
- stronger cryptographic and config validation paths,
- and substantial documentation/auditability improvements.

### Details

- Wrapper lifecycle and upgrade path:
    - Introduced `ezfs2fa_lib/wrapper_upgrade.py` to support wrapper upgrades (notably 3.0.0 -> 3.0.1) without bloating orchestration code.
    - Added `--upgrade-wrappers` flow support in CLI orchestration to make wrapper version migration explicit and repeatable.
    - Added `ezfs2fa_versions.json` as a structured core/wrapper version reference.

- Key wrapping logic refactor and hardening:
    - Moved key wrap/unwrap business logic into `ezfs2fa_lib/key_wrap.py` to isolate crypto-centric code from CLI orchestration.
    - Increased validation rigor around wrappers and factor metadata consistency.
    - Updated derivation internals to HKDF-SHA-512 for wrapper key derivation in the upgraded wrapper format.

- Sensitive material handling improvements:
    - Migrated key/passphrase transient handling from immutable `bytes` usage to mutable `SecretKeyBytes` (`bytearray`) paths where feasible.
    - Added explicit best-effort wiping of transient secret material after use.
    - Improved FIDO CLI output parsing with strict base64/length validation.

- Reliability and operational safety updates:
    - Added deterministic `keylocation=prompt` repair behavior in unlock/recovery paths to reduce interruption-race fallout.
    - Strengthened config schema validation and dataset naming safety (`safe_name()` explicit failure when nothing valid remains).
    - Expanded ZFS helper coverage and `doctor` inventory behavior for imported/importable pools and dataset checks.
    - Standardized FreeBSD scratch buffer behavior to a fixed 1 MiB buffer, aligned with current key-loading needs.

- Documentation and developer-facing updates:
    - Added dedicated wrapper documentation: `KEY_WRAP.md` and `KEY_WRAP_DETAILED.md`.
    - Expanded `DOCUMENTATION.md` and `README.md` to reflect wrapper/doctor/scratch/security behavior changes.
    - Added PlantUML workflow/ceremony diagrams, SVG exports, and conversion helper script under `docs/`.
    - Included supporting media/roadmap/badge refreshes tied to the release cycle.

## 2026-05-22 - v1.1.0

### Summary

Expand `eZFS2FA+` from a FreeBSD/Linux-focused workflow into a broader cross-platform implementation, with:

- Windows support,
- a new Python FIDO2 backend (only option support on Windows and new default option on FreeBSD and Linux),
- and a new `keyformat=hex` key-loading path.

### Details

- Added cross-platform OS handling and privilege flow:
    - `common.py` now includes `current_os()`, a Windows installed config path (`%ProgramData%\ezfs2fa\ezfs2fa.json`), Windows admin detection/elevation support (`runas` relaunch), and a `RelaunchRequested` control-flow exception.
    - `require_root()` now supports Windows Administrator elevation instead of only POSIX `geteuid`.
    - Permission hardening helpers were made more robust (`chmod_private` catches broader OS-level errors).

- Introduced a new Python FIDO backend and backend auto-selection:
    - New file `ezfs2fa_lib/fido_python.py` implements a full cross-platform `python-fido2` backend.
    - On Windows it uses native WebAuthn (`WindowsClient`) with system credential picker flow.
    - On non-Windows hosts it uses HID/CTAP with interactive PIN/touch prompts.
    - `fido.py` now selects backend dynamically (Windows: Python backend only; non-Windows: Python preferred with CLI fallback), and surfaces dependency diagnostics when unavailable.

- Improved CLI FIDO fallback/backend behavior (`fido_cli.py`):
    - Added Windows/MSYS-safe environment handling for `fido2-*` commands.
    - Improved device listing/parsing and probe handling.
    - Added safer fallback selection logic if probe checks fail but devices are discovered.
    - Improved error messages for common Windows/CTAP incompatibility cases.

- Updated core CLI behavior in `ezfs2fa.py`:
    - New `--hex` option on `create` to use `keyformat=hex` with prompt keylocation (still random 32-byte key generated by app).
    - `create` now records dataset `keyformat` in config and supports raw/hex key workflows accordingly.
    - `unlock` now detects dataset keyformat and uses the correct load method (`raw` scratch file vs `hex` prompt injection).
    - Added early FIDO availability validation when FIDO is requested.
    - `doctor` now reports selected FIDO backend, Python FIDO availability, OS-specific required/optional tooling, and updated scratch mode reporting.
    - `fido-list -D` behavior is backend-aware, with explicit warning when `-D` is ignored on Windows WebAuthn.
    - `list` now shows per-dataset `keyformat`.
    - Backup/export/pack commands use shared secure chmod helper.
    - Main entrypoint now handles elevation relaunch flow cleanly.

- Extended scratch and ZFS operation layers:
    - `scratch.py` now supports Windows compatibility mode using a private temp directory when RAM-backed mounts are unavailable.
    - Added hex-key support helpers in `zfsops.py`:
    - key normalization/validation and prompt helpers
    - create/load/change key operations for `keyformat=hex`
    - file URI normalization via absolute `file://` URI helper for raw key paths
    - Added additional zpool helper routines (`scan_pool_inventory`, `import_zpool`, `export_zpool`, force-hint detection, richer command error surfacing).

- Added Windows install/uninstall tooling:
    - New `install.ps1` + `install.cmd`:
    - self-elevates to Administrator
    - verifies/bootstraps pip
    - installs `fido2` Python package
    - installs files under `Program Files\eZFS2FA`
    - creates CLI wrapper and updates machine PATH
    - initializes config under ProgramData if missing
    - New `uninstall.ps1` + `uninstall.cmd`:
    - self-elevates
    - removes installed files and PATH entry
    - optionally removes config with explicit confirmation
    - attempts optional `pip uninstall fido2`

- Updated Linux/FreeBSD installer dependency sets (`install.sh`) to include Python FIDO2 packages.

- Documentation and repo hygiene updates:
    - `README.md` and `DOCUMENTATION.md` now describe Windows support, backend selection model, `--hex` workflows, updated dependency guidance, and updated config paths.
    - `KEY_WRAP.md`/`KEY_WRAP_DETAILED.md` were updated (including PBKDF2 iteration note and style/wording cleanup).
    - `.gitignore` now ignores local `ezfs2fa.json`.
